# ② 축 도면 분석 에이전트 단계별 지침

관련 이슈: [#39 — ② 도면 분석 에이전트를 단계별 분석으로 바꾸고 지침을 문서로 남기기](https://github.com/shj8213/CMS-AI-based-blueprint-inspection-agent/issues/39)

**V4는 1차 프로젝트의 단일 축 도면 분석을 위한 저장소 초안입니다. Copilot Studio에 자동 적용되거나 게시되지 않았으며, 무오류를 보장하지 않습니다.** 사람이 원본 도면을 확인해야 합니다. ③ 도면 검토 에이전트 자료는 [README.md](README.md)에 있습니다.

홈페이지의 ② 분석 요청도 단일 축 부품 범위와 형상→치수 연결→공차·끼워맞춤→기하공차·데이텀→표면·주서·KS 표기→전체 대조 순서를 안내합니다. 이 요청문은 Studio에 저장된 지침을 바꾸지 않으며, 실제 결과는 Studio 지침과 연결된 자료 상태에 따라 달라질 수 있습니다.

팀원이 홈페이지에서 내려받아 연습할 수 있도록 기준 도면 `tests/fixtures/shaft-practice-reference.pdf`와 세 가지 의도된 표기 불일치가 있는 비교 도면 `tests/fixtures/shaft-practice-challenge.pdf`를 추가했습니다. 정답표는 [별도 문서](examples/shaft-practice-answer-key.md)에 있으며, 정적 홈페이지에 포함되지 않습니다. 에이전트에 전달할 때에는 비교 도면 PDF 하나만 선택하고 정답표를 전달하지 마세요. 이는 에이전트의 정확도 검증 자료가 아니라 사람이 대조할 수 있는 소규모 가상 연습 예제입니다.

- 지침 초안에는 규격 원문이나 허용값을 복사하지 않았습니다. KS 자료의 판·적용 조건을 확인할 수 없으면 근거 확인 필요로 남기도록 했습니다.
- 실제 도면·정답표·화면 캡처, 계정·환경·에이전트 식별자와 인증 정보는 포함하지 않았습니다.

## 에이전트가 하는 일

1차 범위에서는 단일 축 도면의 실제 형상·위치·치수·공차·도면에 적힌 KS 표기를 순서대로 읽어 JSON으로 정리합니다. 분석은 추출과 연결이며 설계 피드백은 다음 단계입니다. 누락·오류 및 KS/ISO 적합 판정, 가공방법 추천, 도면 수정은 하지 않습니다. 기준 자료를 실제로 열어 판·적용 조건을 확인하지 못하면 그 사실을 남기고, 기억이나 추측으로 규격 조항·값을 만들지 않습니다.

## 6단계 분석과 총 분석

각 단계는 앞 단계 결과를 바탕으로 하고, 끝날 때 자체 점검을 한 뒤 자동으로 다음 단계로 갑니다. 사용자에게 단계마다 확인을 요청하지 않습니다. 확실하지 않은 것은 "확인 필요"로 남기고, 그것과 관계없는 항목은 계속 분석합니다.

| 단계 | 이름 | 하는 일 | 자체 점검 |
| --- | --- | --- | --- |
| 1 | 축 형상 | 단일 축 도면인지 확인하고 전체 윤곽, 지름 구간, 단차·어깨, 홈·키홈·나사·구멍·모따기 후보를 뷰별로 구분합니다. 이 단계에서는 치수를 연결하지 않습니다. | 형상 종류를 추측하지 않았는지, 뷰와 부품 경계·중복 여부 |
| 2 | 치수 읽기와 연결 | 지름·전체 길이·구간 길이·단차 위치와 각 치수선을 실제로 가리키는 형상에 연결합니다. | 치수 표기·단위·위치와 연결 근거, 불확실한 연결을 억지로 확정하지 않았는지 |
| 3 | 치수공차·끼워맞춤 | 각 크기 치수에 붙은 공차·끼워맞춤 원문을 해당 치수와 축 구간에 연결하고 일반공차와 구분합니다. | 공차가 다른 치수로 옮겨 붙지 않았는지, 원문·단위 보존 |
| 4 | 기하공차·데이텀 | 기하공차의 기호·값·데이텀과 실제 지시 대상을 읽습니다. | 데이텀 기호·참조가 확대 판독한 뷰에서 확인되는지 |
| 5 | 표면·재질·주서·KS 표기 | 표면거칠기, 재질·열처리, 표제란·주서와 도면에 직접 적힌 KS 번호·판 표기를 읽습니다. 연결된 승인 자료를 실제로 열어 확인한 경우만 그 근거를 기록합니다. | KS 번호만 보고 규격 내용을 추정하지 않았는지, 근거·판·적용 조건을 확인했는지 |
| 6 | 계산·전체 대조 | 이전 다섯 단계의 표기·연결·근거와 id를 순서대로 대조합니다. | 해결되지 않은 판독·연결·근거가 있으면 단계와 전체 상태를 `완료`로 쓰지 않았는지 |

### v2에서 바뀐 점

v1 재시험 결과를 대조했을 때, 주요 치수와 표는 원문대로 읽었지만 **도면에 있는 표기를 결과에서 빠뜨린 곳**이 있었습니다. 원인과 고친 규칙은 다음과 같습니다. 특정 도면의 값은 지침에 넣지 않았습니다.

| 발견한 원인 | v2 규칙 |
| --- | --- |
| 일부 영역만 확대하고 나머지는 전체 이미지와 글자 추출(OCR)로만 읽음 | 모든 뷰를 한 번씩 확대하기 전에는 한 뷰를 반복 확대하지 않음. 표제란·부품표·주서·표도 확대함 |
| 세로로 쓴 치수 하나를 읽지 못함 | 세로·기울어진 글자는 이미지를 돌려 읽음 |
| 6단계가 내부 번호·합계 검사만 하고 `완료`로 표시함 | 뷰마다 치수선과 읽은 항목을 대조하고, 확대하지 못한 뷰가 있으면 6단계와 전체 상태를 `완료`로 두지 않음 |
| 공차틀이 참조하는 데이텀 기호를 확대하지 않은 영역에서 찾지 못함 | 모든 뷰를 확대한 뒤에도 없을 때만 `발견하지 못함`, 아니면 `확인 필요` |
| 원문 칸(`raw_text`)에 "판독 불가" 같은 설명을 덧붙이고, 여러 표기를 한 항목에 묶음 | 원문 칸에는 보이는 글자만 쓰고 못 읽은 글자는 `?`. 설명은 `confidence_reason`에 쓰고, 표기 하나는 항목 하나 |

JSON에는 뷰마다 `read_coverage`(`확대 판독`, `전체 이미지만`, `읽지 못함`)가 추가되어 `schema_version`을 `1.2`로 올렸습니다. 다른 항목은 그대로입니다.

- **총 분석**은 앞 단계 결과만 모아 5줄 이내로 요약합니다. 새로 분석하지 않고 각 내용에 출처 단계를 적으며, 확인 필요 항목을 문제없음으로 바꾸거나 누락·오류로 판정하지 않습니다.
- 응답은 `총 분석` 요약 뒤에 JSON 코드 블록 하나입니다. 기존 JSON 항목에 단계 기록 `stage_log`(단계 번호, 이름, 결과, 점검 내용, 남은 문제)가 더해졌습니다.
- 자체 점검은 사람의 확인을 대신하지 않습니다. 점검에서 고치지 못한 문제는 해당 단계의 `issues`와 `limitations`에 남깁니다.

## Studio에 적용하는 방법

1. 권한이 있는 Studio 환경에서 ② 도면 분석 에이전트 화면을 엽니다. 담당자와 적용 범위를 먼저 확인하고, 다른 사람이 수정한 지침을 덮어쓰지 않습니다.
2. 지침 편집 영역의 내용을 `analyzer-instructions-staged-v2.txt` 전체로 바꾸고 저장합니다. 게시하지 않고, 인증·웹 연결 설정은 바꾸지 않습니다.
3. 새로고침한 뒤에도 같은 내용인지 확인합니다. 접근할 수 없으면 관리자에게 요청하고 확인을 완료로 표시하지 않습니다.

도구·지식·메모리 설정은 이 파일에 포함되지 않습니다. 확인한 상태는 다음과 같습니다.

- 메모리: 꺼져 있었습니다.
- 도구: 도구 카드를 열면 `도구 추가` 창만 열렸고 연결된 도구 목록은 보이지 않았습니다. 창만 닫았고 아무것도 추가하지 않았습니다. 상세 설정을 모두 확인한 것은 아니므로 도구가 없다고 단정하지 않으며, 지침으로 웹 검색·조직 문서·장기 메모리를 쓰지 않도록 했습니다.

## 참고 예제(학습) 지식 v3

`analyzer-instructions-staged-v4.txt`는 1차 범위를 단일 축으로 좁히고, 사용자가 강조한 순차 분석과 치수공차·끼워맞춤·KS 표기 확인을 반영한 초안입니다. 도면 표기는 원문대로 기록하고, KS 근거는 연결된 자료를 실제로 열어 판·적용 조건을 확인한 경우에만 사용합니다. 규격 적합 판정은 하지 않으며, 이 초안은 아직 Copilot Studio에 적용되거나 게시되지 않았습니다.

1. 홈페이지 첫 화면의 **저장된 ② 분석 결과**에서 도면과 직접 비교해 맞는 결과만 **확인 완료**를 체크하고 **참고 예제 파일 내려받기**를 누릅니다. 공개해도 되는 도면만 체크합니다.
2. 내려받은 `blueprint-reading-reference-examples.txt`를 열어 사람 이름·연락처·기밀 정보가 없는지 확인합니다.
3. Studio의 ② 화면에서 **지식** → **지식 추가** → **파일 업로드**로 이 파일을 올립니다. 예제를 바꿀 때는 이전 파일을 지우고 새 파일을 올립니다.
4. V4는 이슈 범위와 팀의 기준 자료·출처 검토가 끝난 뒤 권한 있는 담당자가 Studio에 별도로 적용·시험해야 합니다. Git 변경만으로 Studio가 바뀌지 않으며, 게시하지 않았습니다.

주의할 점:
- 올린 파일은 ②를 편집할 수 있는 팀원과 Microsoft 서비스에서 보고 처리할 수 있습니다.
- 사람이 확인하지 않은 결과를 올리면 틀린 읽기 방식이 다음 분석에 옮겨갈 수 있습니다.
- 예제가 많아지면 응답 시간과 사용량이 늘 수 있습니다. ②가 분석할 때 실제로 예제를 찾아 쓰는지, 정확도가 좋아지는지는 확인하지 않았습니다. 적용 후 같은 시험 도면으로 v2와 결과를 비교해야 합니다.

## 시험 상태

도면 PDF, 정답표, 결과 원문은 저장소에 올리지 않았습니다.

**v1 첫 시험(임시 에이전트)**
- 직접 만든 예제 축 부품도로 임시 에이전트의 미리 보기에서 한 번 실행했고, 이후 임시 에이전트는 삭제했습니다. 지침을 설계할 때 본 도면이라 독립적인 시험이 아니며, 결과 원문은 보존하지 않았습니다.

**v1 재시험(현재 ②)**
- 개인정보를 제거한 비기밀 연습 도면(여러 부품이 한 장에 있는 1쪽 스캔)으로 현재 ②의 미리 보기에서 한 번 실행했습니다.
- 총 분석, 1~6단계 기록, 전체 결과 JSON이 나왔고 전체 상태는 `부분 완료`였습니다. 처음 응답이 길어져 같은 대화에서 마무리를 한 번 더 요청했습니다.
- 결과 JSON의 문법, id 중복·참조, 직렬 치수 합계는 Python 표준 라이브러리로 검사해 통과했습니다.
- Copilot이 도면과 결과를 대조했습니다. 주요 치수와 표의 행은 원문대로 읽었고, 이상해 보이는 표기도 임의로 보정하지 않았습니다. 그러나 세로로 쓴 치수 하나, 확대하지 않은 영역의 구멍·키홈·폭 치수와 데이텀 기호를 결과에서 빠뜨렸고, 원문 칸에 설명을 덧붙였습니다. 이 결과로 v2를 만들었습니다.
- 이 대조는 Copilot의 확인이며 학생의 직접 대조를 대신하지 않습니다. 모든 작은 공차 값은 판정하지 않았습니다.

**v2 시험(현재 ②)**
- v1 첫 시험에 쓴 직접 만든 예제 축 부품도(일부러 5곳을 뺀 1쪽 벡터 PDF)를 현재 ②의 미리 보기 새 대화에 첨부만 해서 한 번 실행했습니다. 정답이나 누락 힌트는 주지 않았습니다.
- 총 분석, 1~6단계 기록, 전체 결과 JSON이 한 번에 나왔고 전체 상태는 `완료`, 모든 뷰의 `read_coverage`는 `확대 판독`이었습니다.
- 결과 JSON의 문법, id 중복·참조, 직렬 치수 합계는 Python 표준 라이브러리로 검사해 통과했습니다.
- Copilot이 도면·정답표와 대조했습니다. 일부러 뺀 5곳을 모두 `발견하지 못함`이나 "공차 표기 없음"으로 기록했고, 다른 치수로 계산할 수 있는 길이는 `계산 가능`으로 두어 누락처럼 다루지 않았습니다. 도면의 표기는 모두 결과에 있었고, 도면에 없는 표기를 만들지 않았습니다.
- 에이전트는 확대 이미지를 4장으로 제한하고, 여러 영역을 한 장에 약 1.2배로만 확대하고도 `확대 판독`으로 기록했습니다.
- 이 도면은 단순하고 지침을 설계할 때 본 도면이라 독립적인 시험이 아닙니다. v2를 만든 계기인 여러 부품 스캔 도면으로는 v2를 시험하지 않았습니다.
- 이 대조는 Copilot의 확인이며 학생의 직접 대조를 대신하지 않습니다.

**V4 설계용 홈페이지 시험(현재 ②, 2026-11-11)**
- 개인정보·기밀이 없는 한 장짜리 가상 계단 축 PDF를 홈페이지에서 ②로 전송했습니다. 이 시험에서만 Microsoft Copilot Studio 사용량이 발생할 수 있습니다. 합성 PDF와 원문 응답은 저장소에 추가하지 않았습니다.
- ②는 JSON으로 파싱 가능한 결과와 1~6단계 기록을 반환했습니다. 형상·치수 표기를 읽고, 애매한 `D20 step` 연결, 도면 주서와 단차 수의 차이, 단위·공차·KS 근거가 없는 부분을 확인 대상으로 남겼습니다.
- 개선점도 확인했습니다. ②의 전체 `status`는 `완료`였지만 2단계는 `확인 필요`였습니다. 홈페이지 코드에 이처럼 전체 상태와 단계 상태가 충돌하면 확인 필요 경고를 추가했습니다. 응답 요약에 분석과 무관한 영어 문장도 섞여 있어 출력 정리가 필요합니다.
- ③은 전송하지 못했습니다. 로컬 ③ 연결 주소가 URL 형식이 아니어서 홈페이지가 전송 전에 중단했습니다. 따라서 이 실행은 ② 분석만 시험했고, 후속 피드백은 검증하지 않았습니다.
- 이 시험은 한 개의 가상 도면에 대한 에이전트 시험이며, 정확도나 KS 지식의 적합성을 입증하지 않습니다. KS 표기가 없는 예제였으므로 규격 판정도 시험하지 않았습니다.

비교 기준이 되는 이전 사람 대조 기록은 [#31 대조 기록 댓글](https://github.com/shj8213/CMS-AI-based-blueprint-inspection-agent/issues/31#issuecomment-6578837902)에 있습니다. 이 기록은 이전 ③ 시험의 대조이며 이번 단계별 ② 결과를 대조한 것이 아닙니다.

## 학생이 따라 할 확인 순서

1. 확인 순서: 최신 지침 초안 `analyzer-instructions-staged-v4.txt`를 검토합니다. Studio에 자동 적용되거나 게시된 상태로 간주하지 않습니다.
   기대 결과: 축 단일 부품 범위, 단계 순서, 공차·KS 자료 제한을 팀이 확인합니다.
2. 확인 순서: 미리 보기에서 **새 대화**를 열고 개인정보·기밀이 없는 시험 도면 PDF를 첨부해 분석을 요청합니다. 정답표나 누락 목록은 보내지 않습니다. 사용량이 발생할 수 있습니다.
   기대 결과: 5줄 이내의 `총 분석`과 JSON 코드 블록이 나옵니다. 문장·값이 매번 같을 필요는 없습니다.
3. 확인 순서: JSON의 `stage_log`를 확인합니다.
   기대 결과: 1~6단계가 순서대로 나오고, 형상→치수 연결→공차→기하공차→표면·주서·KS 표기 순으로 점검합니다.
4. 확인 순서: JSON의 `pages` → `views`에서 뷰마다 `read_coverage`를 확인합니다.
   기대 결과: 모든 뷰에 값이 있습니다. `확대 판독`이 아닌 뷰가 있으면 6단계와 전체 `status`가 `완료`가 아니고, 그 뷰가 `limitations`에 적혀 있습니다.
5. 확인 순서: 도면과 결과를 직접 비교하고 맞은 점·틀린 점·못 읽은 점·`확인 필요`로 남은 점을 #39에 기록합니다. 뷰마다 도면의 치수 표기가 결과에 있는지 살펴봅니다.
   기대 결과: 확실하지 않은 것은 `확인 필요`로 남고 누락·오류로 단정하지 않습니다. 학생 본인이 실제 비교한 근거가 남습니다.

## 남은 범위와 한계

- v1은 도면 2건, v2는 축 도면 1건으로 한 번씩만 시험했고, 시험한 도면은 모두 지침 설계에 쓰였습니다. 학생의 직접 대조는 아직 하지 않았습니다. 다양한 도면·반복 실행의 일관성과 정확도는 확인하지 않았습니다. 정확도 평가는 #34에서 이어갑니다.
- 에이전트가 확대 이미지 수를 스스로 제한하므로, 뷰가 많은 스캔 도면에서는 모든 뷰를 충분히 확대하지 못하고도 `확대 판독`으로 기록할 수 있습니다. 확인하지 않았습니다.
- v2는 모든 뷰를 확대하므로 응답 시간과 사용량이 v1보다 늘 수 있습니다. 실제로 얼마나 늘어나는지는 확인하지 않았습니다.
- ③ 도면 검토 에이전트가 `stage_log`와 `read_coverage`를 어떻게 다루는지는 확인하지 않았고, ③ 지침은 바꾸지 않았습니다(#32).
- 결과 JSON이 매우 길어질 수 있습니다(v1 재시험 결과는 약 10만 바이트). 사람이 읽기 쉽게 보여주는 일은 #40에서 다룹니다.
- V4 초안을 Studio에 적용·게시하지 않았습니다. ③ 연결도 현재 설정 오류로 실제 피드백을 확인하지 못했습니다.
- KS 공식 자료의 실제 연결·판·적용 범위는 이 코드 작업에서 확인하지 않았습니다. 기준 자료를 승인 근거로 썼다고 주장하지 않습니다.
