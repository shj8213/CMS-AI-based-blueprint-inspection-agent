# ② 도면 분석 에이전트 단계별 지침

관련 이슈: [#39 — ② 도면 분석 에이전트를 단계별 분석으로 바꾸고 지침을 문서로 남기기](https://github.com/shj8213/CMS-AI-based-blueprint-inspection-agent/issues/39)

**이 자료는 Copilot Studio의 ② 도면 분석 에이전트에 저장한 지침 원문과 적용·확인 방법입니다. 모든 도면을 정확히 읽는다는 보증이 아니며, 사람이 도면을 직접 확인하는 일을 대신하지 않습니다.** ③ 도면 검토 에이전트 자료는 [README.md](README.md)에 있습니다.

## 포함한 자료와 현재 상태

| 파일 | 용도 |
| --- | --- |
| [analyzer-instructions-staged-v1.txt](analyzer-instructions-staged-v1.txt) | ② 도면 분석 에이전트에 저장한 단계별 지침 원문 |

- 지침 끝 개행을 제외하면 4,341자(66줄)이며, SHA-256은 `9963d98b04f273ee8d628c1bd8fbddaa29a095366b9ee45c2b9e5b79b1c783c8`입니다. SHA-256은 같은 내용인지 확인하는 값이지 답이 정확하다는 증거는 아닙니다.
- Studio의 ② 도면 분석 에이전트는 이 지침을 저장한 **게시하지 않은 초안**입니다. 저장 후 새로고침해 같은 내용인지 확인했습니다.
- 이 파일을 Git에 추가해도 Studio에 자동 반영되거나 게시되지 않습니다. Studio 전체 에이전트 내보내기 파일도 아닙니다.
- 실제 도면·PDF·정답표·화면 캡처, 계정·환경·에이전트 식별자와 인증 정보는 포함하지 않았습니다.

## 에이전트가 하는 일

사용자가 올린 도면을 직접 읽고, 실제로 있는 요소·위치와 형상-치수 연결을 다른 에이전트가 쓸 JSON으로 정리합니다. 사용자에게 검사 항목이나 누락 목록을 요구하지 않습니다. 누락·오류 판정, KS/ISO 적합 판정, 가공방법 추천, 도면 수정은 하지 않고, 읽지 못한 것을 설계 오류로 판단하지 않습니다.

## 6단계 분석과 총 분석

각 단계는 앞 단계 결과를 바탕으로 하고, 끝날 때 자체 점검을 한 뒤 자동으로 다음 단계로 갑니다. 사용자에게 단계마다 확인을 요청하지 않습니다. 확실하지 않은 것은 "확인 필요"로 남기고, 그것과 관계없는 항목은 계속 분석합니다.

| 단계 | 이름 | 하는 일 | 자체 점검 |
| --- | --- | --- | --- |
| 1 | 영역·형상 | 페이지·뷰·부품 번호·표제란 영역을 나누고, 축 지름 구간·구멍·홈·키홈·모따기·나사·단차 등 형상을 나눕니다. 이 단계에서는 치수를 연결하지 않습니다. | 형상이 속한 뷰·부품, 같은 형상의 중복 |
| 2 | 치수 읽기와 연결 | 모든 치수를 읽고, 치수선·보조선·지시선이 실제로 가리키는 형상의 속성에 연결합니다. 연결 상태를 `연결됨`, `연결 확인 필요`, `계산 가능`, `발견하지 못함`으로 기록합니다. | 깊이·폭 치수의 잘못된 연결, 연결되지 않은 치수 |
| 3 | 치수공차·끼워맞춤 | 각 크기 치수에 함께 적힌 공차·끼워맞춤 원문을 그대로 기록합니다. | 공차 기호가 옆 치수로 옮겨 붙지 않았는지 |
| 4 | 기하공차·데이텀 | 기하공차 틀의 기호·값·데이텀과 지시 대상, 데이텀 기호의 위치를 읽습니다. | 참조한 데이텀 문자가 도면에 있는지(없으면 `발견하지 못함`으로만 기록) |
| 5 | 표면거칠기·주서·표제란 | 거칠기 기호와 지시 대상, 주서 문장, 표제란·부품표의 항목명과 값을 짝지어 읽습니다. 빈 칸은 `기입 내용 발견하지 못함`으로 씁니다. | 각 행의 품번·이름·재질·수량이 같은 행에서 왔는지 |
| 6 | 계산·전체 대조 | 같은 방향의 직렬 치수와 전체 치수를 비교하고, 다른 치수로 구할 수 있는 값만 `계산 가능`으로 바꿉니다. | 읽은 값을 `발견하지 못함`으로 쓰지 않았는지, 모든 id가 존재하는지 |

- **총 분석**은 앞 단계 결과만 모아 5줄 이내로 요약합니다. 새로 분석하지 않고 각 내용에 출처 단계를 적으며, 확인 필요 항목을 문제없음으로 바꾸거나 누락·오류로 판정하지 않습니다.
- 응답은 `총 분석` 요약 뒤에 JSON 코드 블록 하나입니다. 기존 JSON 항목에 단계 기록 `stage_log`(단계 번호, 이름, 결과, 점검 내용, 남은 문제)가 더해졌습니다.
- 자체 점검은 사람의 확인을 대신하지 않습니다. 점검에서 고치지 못한 문제는 해당 단계의 `issues`와 `limitations`에 남깁니다.

## Studio에 적용하는 방법

1. 권한이 있는 Studio 환경에서 ② 도면 분석 에이전트 화면을 엽니다. 담당자와 적용 범위를 먼저 확인하고, 다른 사람이 수정한 지침을 덮어쓰지 않습니다.
2. 지침 편집 영역의 내용을 `analyzer-instructions-staged-v1.txt` 전체로 바꾸고 저장합니다. 게시하지 않고, 인증·웹 연결 설정은 바꾸지 않습니다.
3. 새로고침한 뒤에도 같은 내용인지 확인합니다. 접근할 수 없으면 관리자에게 요청하고 확인을 완료로 표시하지 않습니다.

도구·지식·메모리 설정은 이 파일에 포함되지 않습니다. 확인한 상태는 다음과 같습니다.

- 메모리: 꺼져 있었습니다.
- 도구: 도구 카드를 열면 `도구 추가` 창만 열렸고 연결된 도구 목록은 보이지 않았습니다. 창만 닫았고 아무것도 추가하지 않았습니다. 상세 설정을 모두 확인한 것은 아니므로 도구가 없다고 단정하지 않으며, 지침으로 웹 검색·조직 문서·장기 메모리를 쓰지 않도록 했습니다.

## 시험 상태

- 시험 도면은 직접 만든 예제 축 부품도이며, 도면 PDF와 정답표는 저장소에 올리지 않았습니다.
- 같은 지침을 넣은 임시 에이전트의 미리 보기에서 시험 도면 1건을 한 번 실행했고, 이후 임시 에이전트는 삭제했습니다. 이 도면은 지침을 설계할 때 이미 본 도면이므로 독립적인 시험이 아닙니다.
- 그때의 결과 원문은 보존하지 않았습니다. 따라서 이 문서는 그 결과를 완료 근거로 인용하지 않으며, 아래 확인 순서로 현재 ②에서 다시 시험해야 합니다.
- 비교 기준이 되는 이전 사람 대조 기록은 [#31 대조 기록 댓글](https://github.com/shj8213/CMS-AI-based-blueprint-inspection-agent/issues/31#issuecomment-6578837902)에 있습니다. 이 기록은 이전 ③ 시험의 대조이며 이번 단계별 ② 결과를 대조한 것이 아닙니다.

## 학생이 따라 할 확인 순서

1. 확인 순서: Studio에서 ② 도면 분석 에이전트의 지침을 열어 `analyzer-instructions-staged-v1.txt`와 같은지 확인합니다. 게시하지 않습니다.
   기대 결과: 내용이 같고, 에이전트는 게시되지 않은 초안입니다.
2. 확인 순서: 미리 보기에서 **새 대화**를 열고 개인정보·기밀이 없는 시험 도면 PDF를 첨부해 분석을 요청합니다. 정답표나 누락 목록은 보내지 않습니다. 사용량이 발생할 수 있습니다.
   기대 결과: 5줄 이내의 `총 분석`과 JSON 코드 블록이 나옵니다. 문장·값이 매번 같을 필요는 없습니다.
3. 확인 순서: JSON의 `stage_log`를 확인합니다.
   기대 결과: 1~6단계가 나오고, 각 단계에 점검 내용과 남은 문제가 있습니다.
4. 확인 순서: 도면과 결과를 직접 비교하고 맞은 점·틀린 점·못 읽은 점·`확인 필요`로 남은 점을 #39에 기록합니다.
   기대 결과: 확실하지 않은 것은 `확인 필요`로 남고 누락·오류로 단정하지 않습니다. 학생 본인이 실제 비교한 근거가 남습니다.

## 남은 범위와 한계

- 설계할 때 본 도면으로 한 번 시험했을 뿐이며, 다양한 도면·반복 실행의 일관성과 정확도는 확인하지 않았습니다. 정확도 평가는 #34에서 이어갑니다.
- 지침을 교체한 뒤 현재 ②에서의 재시험과 학생의 직접 대조는 아직 하지 않았습니다.
- ③ 도면 검토 에이전트가 새 `stage_log` 항목을 어떻게 다루는지는 확인하지 않았고, ③ 지침은 바꾸지 않았습니다.
- 결과 JSON이 매우 길어질 수 있습니다(시험 때 약 6만 5천 자로 기록했으나 원문은 보존하지 않았습니다). 사람이 읽기 쉽게 보여주는 일은 #40에서 다룹니다.
- 게시, 인증·웹 연결, 홈페이지 연동은 이번 범위가 아닙니다.
