# Studio ② 에이전트에 DXF 읽기 도구 추가하기 (준비 안내)

> 이 문서는 **준비 안내**예요. Studio 설정은 에이전트 소유자(방장)가 직접 바꿔야 해요. 아래 시험을 통과하기 전에는 "DXF를 분석한다"고 말하지 않아요.

## 왜 필요한가요?
- 지금 ② 에이전트는 DXF를 읽는 도구가 없어서 "미지원 형식"으로 답해요(`analyzer-instructions-staged-v3.txt`).
- 그래서 홈페이지의 "도면 분석하기"는 PDF만 돼요. DXF는 "이 브라우저에서만 읽기"를 써요.

## 먼저 정해야 할 것 (방장 확인)
1. **어떤 도구를 쓸까요?** Studio에서 코드 실행 또는 DXF를 PDF·이미지로 바꾸는 기능을 쓸 수 있는지 확인해요. 없으면 이 방법은 진행할 수 없어요.
2. **전송 범위**: DXF 파일이 Microsoft 서비스로 전송돼요. 기존 PDF와 같은 보관 기간(마지막 활동 후 28일)인지 확인해요.
3. **비용**: 도구 실행으로 사용량이 늘 수 있어요. 허용 범위를 정해요.
4. **개인정보**: 도면에 개인정보·기밀이 없는 자료만 써요.

## 소유자가 할 일
1. Studio에서 ② 에이전트를 열어요.
2. DXF를 읽는 도구를 추가해요(위 1번에서 정한 방식).
3. 지침의 DXF 문장을 바꿔요. 도구가 실제로 동작할 때만 아래처럼 쓰고, 동작하지 않으면 기존 "미지원 형식" 문장을 그대로 둬요.
   - 예: "DXF는 연결된 DXF 읽기 도구로 분석하고, 도구가 실패하면 '미지원 형식'으로 PDF·이미지 변환을 안내합니다."
4. 도구 이름만으로 기능이 있다고 주장하지 않아요. 실제로 실행한 도구만 근거로 써요.

## 시험 방법
1. 개인정보 없는 가상 DXF(`tests/fixtures/review-a.dxf`, `review-b.dxf`, `review-c.dxf`, `simple.dxf`)를 Studio 테스트 창에 올려요.
2. 기대 결과: 선·원·글자와 위치가 ② 형식 JSON(`schema_version` 1.1)으로 나와요. 읽지 못한 부분은 "확인 필요"로 표시돼요.
3. 실패하면 이유를 쉬운 말로 알려 주고 "문제없음"이라고 하지 않아요.
4. 홈페이지 `studio-connection.js`는 지금 PDF만 보내요. Studio 시험이 통과한 뒤 별도 작업으로 DXF 전송을 열어요.

## 되돌리는 방법
Studio 지침을 이전 버전으로 되돌리고 추가한 도구를 끄면 돼요. 홈페이지는 이 문서 때문에 바뀌지 않아요.
