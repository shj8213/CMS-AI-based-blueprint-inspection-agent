# 누락 탐지 성능 시험

[#31](https://github.com/shj8213/CMS-AI-based-blueprint-inspection-agent/issues/31)의 Copilot Studio 에이전트를 **도면만 보고** 시험하는 오프라인 준비 도구예요. 웹사이트·에이전트 지침·원본 도면을 수정하지 않아요.

## 현재 상태

**2026-11-08에 `trial-01` 실제 에이전트 시험을 진행했고 사용자가 전체 응답과 결과 분류의 대조를 완료했다고 확인했어요.** 사용자가 시험 전에 알려 준 정답은 D017의 MATERIAL 값 누락, D042의 누락 없음이에요. 이 사전 기록은 [정답 파일](trial-01/evaluator-only/answers.json)에 보존했어요. 도면별 새 대화에 PDF 하나와 요청문만 전달했어요. 결과는 [진행 기록](results.md)과 [시험 보고서](trial-01-report.md)에 있어요. D017 공차, D042 공차 및 합금 종류 지적은 오탐으로 확정하지 않고 판단 보류했어요. D042의 도면 번호·개정·척도·투상법도 별도 보류 메모에 있어요. `human_reviewed`는 `true`예요. 부가 JSON 전문은 Studio 대화에만 있고 이 작업 폴더에는 옮기지 않았어요. 문서는 아직 팀과 공유하지 않았고 #34 전체도 완료되지 않았어요.

## 준비와 정답 확인

Python 3.9 이상에서 저장소 루트를 기준으로 실행하세요. 외부 패키지·로그인·다운로드가 필요 없어요.

```powershell
python tools\omission_evaluation.py prepare evaluation\trial-02
python -m unittest discover -s tests -p test_omission_evaluation.py -v
```

`trial-01`은 실제 시험 기록이 있으므로 다시 만들거나 덮어쓰지 마세요. 새 시험을 준비할 때만 다른 이름을 사용해요. 이미 있는 폴더는 덮어쓰지 않아요.

| 경로 | 용도 | 에이전트 전달 |
|---|---|---|
| `trial-01\agent-input\D017.pdf`, `D042.pdf` | 비기밀 직접 제작 단일 페이지 PDF | 한 번에 하나만 |
| `trial-01\agent-input\request.txt` | 두 도면에 동일하게 사용하는 요청 | 전달 |
| `trial-01\evaluator-only\answers.json` | 도면별 정답 초안·파일 지문 | **전달 금지** |
| `trial-01\evaluator-only\results.json` | 응답 원문·사람의 대조 판단 | **전달 금지** |

평가 담당자만 아래 정답을 확인하세요. 도면 검토자와 별도 사람이 맡는 것이 좋아요. 사람이 두 PDF를 직접 열어 정답을 **독립적으로 작성하거나 초안을 수정·확인한 뒤** `answers.json`의 `human_approved`를 `true`로 바꿔요. 정상 예제에도 다른 누락이 있다면 정답을 수정하세요.

- D017: 상단 `MATERIAL` 칸이 비어 있어요. 정답 초안의 `material` 항목이에요.
- D042: 재질 `ALUMINUM`, 폭 25, 길이 70, 두께 5, 단위 mm가 있어요. 이 단순 연습도 범위에서는 의도한 누락이 없어요.
- 두 도면은 제조나 규격 적합성을 보증하는 도면이 아니에요. 치수의 선형 축척·일반공차·표면거칠기 등을 제조 기준으로 평가하려면 이번 시험의 정답을 먼저 사람이 재검토해야 해요.

이 문서·저장소 전체·평가자 폴더를 에이전트의 지식이나 첨부에 넣지 마세요. **폴더 분리는 접근 권한 차단이 아니에요.** 도면만 별도 첨부하고 검색 가능한 자료에도 정답이 없는지 확인하세요. 중립 파일명은 누락 여부를 말해 주지 않지만 내용 자체의 차이를 숨기지는 않아요.

## 실제 시험과 기록

1. #31 에이전트가 준비됐는지 사람이 확인하고, 버전·시험일·동일한 설정을 기록해요. 도면별 새 대화를 열어 정상본과 누락본이 서로 힌트가 되지 않게 해요. `trial-01`은 D017 20:14, D042 20:18 KST에 각각 새 대화로 진행했어요.
2. 해당 PDF 하나와 `request.txt`만 전달해요. 정답·누락 종류·검사 목록은 전달하지 않아요. 응답이 끊겼다면 재시도 사실도 기록하고 완성 응답을 받기 전에는 `completed`로 처리하지 않아요. `trial-01`은 ② 분석 결과 없이 ③ 도면 검토 에이전트에 PDF를 직접 첨부했어요.
3. 실제 응답 본문과 부가 JSON은 구분해 기록해요. `trial-01`에는 응답 본문과 부가 JSON 기록 메모가 있지만 부가 JSON 전문은 Studio 대화에만 있어요. 전문 전체를 이 작업 폴더에 옮겼다고 주장하지 않아요. `mode`는 실제 응답이면 `actual`, 도구 검사용 가짜 응답이면 `mock`이에요. `agent_version`, `run_date`를 기록해요.
4. 사람이 응답의 **모든 누락 지적과 불확실한 지적**을 `findings`에 하나씩 옮기고 대조해요. 도구는 자유 문장을 자동 해석하지 않으므로 항목을 빼먹으면 오탐이 적게 집계될 수 있어요. 두 번째 팀원의 원문 검토를 권장해요.
5. 사람이 대조를 마친 뒤에만 `human_reviewed`를 `true`로 바꿔요. 코파일럿이 작성한 비교 초안이나 시험 전 정답 확인만으로 이 값을 바꾸지 않아요. 같은 정답을 두 번 찾았다고 세지 않아요.

`results.json`에서 D017 하나의 기록 예시예요. **다음은 입력 형식 설명용 가짜 응답이며 실제 시험 결과가 아니에요.** 이 예시를 사용할 때 전체 `mode`는 반드시 `mock`이어야 해요.

```json
{
  "state": "completed",
  "response": "1페이지 상단 재질 칸이 비어 있습니다.",
  "findings": [
    {
      "quote": "1페이지 상단 재질 칸이 비어 있습니다.",
      "decision": "match",
      "omission_id": "material",
      "reason": "사람이 도면과 대조했고 정답의 위치와 의미가 같습니다."
    }
  ]
}
```

| `decision` | 사람이 적용할 기준 |
|---|---|
| `match` | 정답과 **같은 정보·같은 도면 위치**의 누락을 명확히 지적함. `omission_id`로 연결 |
| `false_positive` | 원본과 정답을 대조해 누락이 아닌데 빠졌다고 단정한 지적. `reason`에 반증 기록 |
| `pending` | 판독 불확실·확인 필요·위치 불명·정답 범위 밖 의견 등 사람이 확정하지 못함 |

“확인 필요”는 찾은 누락이나 오탐으로 자동 계산하지 않아요. 같은 의미인지 모호하면 `pending`으로 두세요. 정답에 없는 지적도 실제 누락일 수 있으므로 곧바로 오탐으로 정하지 말고 사람이 검토해요. 정답 수정이 필요하면 이유를 기록하고 이전 기록을 보존한 새 시험으로 진행해요.

아무 누락도 지적하지 않은 **완전한 응답**은 `completed`와 빈 `findings`로 기록해요. 아예 실행하지 않은 도면은 `not_run`을 유지해요.

```powershell
python tools\omission_evaluation.py report evaluation\trial-02 evaluation\trial-02-report.md
```

보고서는 도면별 **찾은 누락·놓친 누락·잘못 지적한 항목·판단 보류**, 응답 원문, 사람이 대응시킨 이유를 담아요. `trial-01-report.md`는 #34에서 요청한 세 항목만 표에 두고, 판단 보류는 별도 메모에 적은 수동 결과예요. D017 공차, D042 공차·합금 종류의 세 지적은 오탐으로 확정하지 않았고, D042의 도면 번호·개정·척도·투상법도 별도 확인 보류예요. 보고서 생성 도구는 `answers.json`의 정답 확인과 `results.json`의 사람 대조 표시가 모두 완료된 뒤에만 실행해요. 기존 파일을 덮어쓰지 않으므로 새 출력 경로를 지정해야 해요. 적은 예제 두 개만으로 일반적인 정확도를 보증하거나 합격 기준을 만들지 않아요.

보고서는 기존 파일을 덮어쓰지 않으며 `agent-input` 안에는 저장할 수 없어요. 원문과 보고서에 개인정보·기밀이 없는지 사람이 확인한 뒤 팀 공유 문서로 보관하세요. 보고서를 GitHub에 올리는 작업은 별도로 승인받아야 해요.
