# Copilot과 함께 만드는 우리 팀 프로젝트

코드를 잘 몰라도 괜찮아요. **할 일을 적고 → Copilot과 만들고 → 직접 확인하는 순서**로 시작해 보세요.
이 저장소에는 협업 안내와 양식, DXF·PDF에서 선·원·글자를 읽는 기능이 있어요. 스캔 PDF는 사진 이미지에서 글자를 찾고, 선·원은 검토할 후보로 표시해요. 전체 읽기 결과를 직접 복사해 홈페이지 안의 실제 Copilot Studio 도면 분석 채팅에 붙여넣고 전송할 수 있어요. 도면 판독과 채팅 답변은 설계 적합성 판정이 아니며, 가공방법 추천·수정본 제작은 아직 홈페이지 기능으로 연결되지 않았어요.

## DXF·PDF 읽기

Python 3가 설치된 상태에서 저장소 폴더의 터미널에 아래 명령을 차례로 입력하세요.

```sh
python3 tools/setup_readers.py
python3 -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 <http://127.0.0.1:8000/>을 여세요. `index.html`을 직접 여는 방식은 모듈·PDF 작업 도구를 불러올 수 없어 지원하지 않아요. 서버는 `Ctrl+C`로 종료해요.

준비 명령은 공개 npm 저장소의 **PDF.js 6.4.299**, **Tesseract.js 6.0.1**, **Tesseract.js Core 6.1.2**와 Tesseract Fast의 한국어·영어 OCR 학습 자료를 내려받아요. npm 패키지는 고정된 SHA-512로, 학습 자료는 고정된 Git 파일 해시로 확인해요. 도구·학습 자료와 라이선스는 `vendor/pdfjs/`, `vendor/tesseract/`에 저장되며 Git에는 포함되지 않아요. 처음 준비할 때 인터넷이 필요하고, 한국어·영어 OCR 자료 약 5.5MB와 실행 도구가 내려받아져요. 그다음부터 모두 로컬에서 읽어요. **선택한 도면 파일은 서버나 외부 서비스로 전송하지 않아요.** Node.js·npm 설치나 빌드 과정은 필요 없어요.

- DXF 또는 PDF를 하나 선택하고 **도면 읽기**를 누르세요. 선·원·글자의 내용과 위치를 표와 미리보기로 보여줘요. PDF는 페이지를 바꿔 확인할 수 있어요.
- DXF는 2차원 모형 공간의 `LINE`, `CIRCLE`, `TEXT`, `MTEXT`, `LWPOLYLINE` 직선 구간을 읽어요. 위치는 원본 좌표이며 오른쪽·위쪽이 +방향이고, 단위는 DXF의 `$INSUNITS`를 표시해요. UTF-8과 일부 명시된 기존 인코딩을 지원해요.
- 일반 PDF는 저장된 직선 경로·글자를 읽어요. 스캔 PDF나 이미지가 들어간 페이지는 한국어·영어 OCR로 이미지 속 글자를 찾고, 이미지 분석으로 선·원 후보를 찾으며 모두 **확인 필요**로 표시해요. OCR 신뢰도가 80%보다 낮은 글자는 인식 신뢰도와 함께 별도 표시해요. OCR은 사진 글자를 추정하는 기능이라 치수와 한글이 틀릴 수 있어 원본과 비교해야 해요.
- PDF 위치는 회전·잘라내기가 반영된 각 페이지 왼쪽 위 기준으로 오른쪽·아래쪽이 +방향이며, 단위는 포인트(1/72인치)예요. 일반 PDF의 원은 네 개의 닫힌 곡선으로부터 추정하므로 **확인 필요**로 표시해요.
- 미리보기는 읽은 요소를 재구성한 것이며 원본 뷰어가 아니에요. 글꼴·서식·정렬·잘림·숨김 표시·선 두께를 재현하지 않아요. 표의 글자 위치는 DXF 삽입점 또는 PDF 글자 시작 기준점이에요.
- 미지원 요소와 이미지 페이지는 **확인 필요**로 안내해요. 스캔 이미지에서 글자를 찾지 못하면 원인을 알려주고, 읽을 수 있는 요소가 전혀 없거나 파일이 손상되면 오류를 표시하며 성공 화면으로 이동하지 않아요.
- 바이너리 DXF, 3차원 도면, 블록 내부 요소, 복잡한 치수·일반 곡선, 암호가 걸린 PDF는 아직 지원하지 않아요. 스캔 PDF의 선·원은 제한된 이미지 탐지의 후보이므로 정확성을 보장하지 않아요. 사진이 기울거나 흐릴 때 OCR·도형 인식률이 낮을 수 있어요.
- **도면 다시 선택**을 누르면 처음 화면으로 돌아가고 복사할 결과와 열린 채팅을 지워요. 파일을 새로 고르거나 읽기에 실패한 뒤에는 이전 결과를 복사할 수 없어요. 가공방법 추천·수정본 영역은 아직 화면 틀이며, 원본 파일을 수정하지 않아요.

### 로그인 없이 도면 분석 채팅에 직접 전달하기

1. 홈페이지에서 DXF·PDF를 **도면 읽기**로 로컬 처리하세요.
2. **복사할 전체 결과와 민감한 내용 확인**을 펼쳐 글자·경고에 개인정보, 고객명, 비공개 도면 정보가 없는지 살펴보세요. 파일명은 제외하지만 도면 속 글자는 남아 있어요. 민감한 내용이 있으면 전송하지 말고 공개 가능한 도면으로 다시 읽으세요.
3. 민감한 내용 확인란을 체크하고 **전체 결과 복사**를 누르세요. 이 단계는 클립보드에만 저장하며 Microsoft로 보내지 않아요.
4. **채팅 열기**를 누르면 승인된 실제 Copilot Studio 공개 웹 채팅을 홈페이지 안에서 불러와요. 입력창에 사용자가 직접 붙여넣고 전송하세요. **자동 전송이 아니에요. 원본 파일은 자동으로 전송하지 않으며 이 채팅에는 파일 첨부 기능도 없어요.**

**채팅을 여는 순간 Microsoft에 접속하며, 붙여넣어 전송한 도면 정보는 Microsoft에서 처리해요.** 로그인 없이 쓰는 공개 채팅이라 사용량에 따라 운영자의 Copilot Studio 크레딧이 소모되거나 비용이 발생할 수 있어요. 사용자 요청 전에는 외부 채팅을 불러오지 않고, 홈페이지는 도면 정보나 파일을 채팅으로 자동 전달하지 않아요. 채팅 닫기·도면 다시 선택·파일 재선택은 삽입된 채팅 화면을 제거하지만, 이미 사용자가 전송한 정보나 발생한 비용을 취소하지는 않아요.

복사하는 JSON에는 `schema_version: "homepage-reader-v1"`, `format`, `unit`, `pages`, `elements`, `warnings`가 들어가요. **현재 표시 페이지나 100개짜리 목록이 아니라 전체 읽기 결과**예요. 빈 결과 페이지를 포함한 모든 페이지 정보, 실제 요소의 좌표·OCR `confidence`·`uncertain`, 이미지 도형 후보와 미지원 경고를 반올림·필터링·확정 없이 그대로 보존해요. `coordinate_note`에는 좌표 해석, `reading_note`에는 판독 한계를 함께 넣어요. PDF 좌표는 각 페이지 왼쪽 위 기준의 포인트(1/72인치)이며 **실제 부품의 mm 치수가 아니에요.** DXF 좌표와 단위는 원본 값 그대로이며 mm로 바꾸거나 단위를 추정하지 않아요. 미지원 요소를 새로 읽어낸 것처럼 만들지 않으며, 기존 읽기 도구가 알려준 누락 경고를 그대로 전달해요.

브라우저의 클립보드 권한·접속 주소 문제로 자동 복사가 실패하면 오류와 전체 JSON을 표시해요. **전체 텍스트 선택** 후 Windows는 `Ctrl+C`, macOS는 `Command+C`로 직접 복사하거나 모바일에서 길게 눌러 전체 선택·복사하세요. 실제로 직접 복사를 마친 뒤 **직접 복사를 마쳤어요**를 누르면 채팅을 열 수 있어요. 자동 복사 실패를 성공으로 표시하지 않아요.

외부 채팅의 표시 여부·로그인 요구·응답 성공은 홈페이지에서 확인할 수 없어요. 입력창이 안 보이면 **같은 채팅을 새 탭으로 열기**를 사용하거나 관리자에게 알려 주세요. 로그인 없는 사용 가능 여부·크레딧 잔액은 실제 Copilot Studio 채널 설정에 달려 있어요. 긴 JSON이 채팅 입력 길이 제한에 걸리면 임의로 잘라서 보내지 말고 관리자에게 알려 주세요. 채팅 답변은 원본과 사람이 대조해야 하며 표·미리보기에는 자동 반영되지 않아요.

### 예제와 자동 검사

개인정보 없는 직접 만든 예제를 `tests/fixtures/`에 두었어요.

| 예제 | 기대 결과 |
|---|---|
| `simple.dxf` | 선 1개: (20, 30) → (140, 30), 원 1개: 중심 (200, 130)·반지름 25, 글자 ‘도면 예제’: (20, 190), 단위 mm |
| `simple.pdf` | 1페이지: 선 (20, 210) → (140, 210), 원 중심 (200, 110)·반지름 25, ‘Hello blueprint’ (20, 50). 2페이지: 회전·잘라내기·중첩 좌표 변환을 반영한 선 2개와 글자 1개, 타원은 제외 안내 |
| `scan.pdf` | 이미지 속 ‘5 mm’를 OCR로 처리해 숫자 ‘5’를 찾고, 낮은 신뢰도의 나머지 글자는 ‘확인 필요’로 표시. 선 (25, 70) → (150, 70), 원 중심 (230, 120)·반지름 약 27.5의 후보도 확인 필요로 표시 |
| `scan-only.pdf` | 글자나 도형이 없는 이미지 PDF. 글자를 찾지 못했다는 안내와 오류 표시 |
| `mixed.pdf` | 첫 페이지의 일반 요소와 둘째 페이지의 이미지 속 OCR 글자·선·원 후보 모두 표시 |
| `paths.pdf` | 사각형의 선 4개와 삼각형의 선 3개, 그리지 않은 경로는 제외 |
| `broken.pdf` | 손상된 PDF라는 오류 안내 |

서버 실행 후 <http://127.0.0.1:8000/tests/>를 열면 브라우저에서 자동 검사가 실행돼요. 개수·좌표·일반 및 스캔 글자·페이지 전환·손상 파일·기존 결과 제거와 함께 전체 JSON 계약, 파일명 제외, 모든 페이지·205개 요소 보존, OCR 신뢰도·후보·경고 보존, 민감한 내용 확인, 복사 성공·거부·미지원 대안, 늦은 복사 완료 뒤 이전 결과 제거, 명시적 채팅 열기·닫기, 360px 모바일 화면 범위와 새 버튼의 44px 이상 높이를 검사해요. 자동 검사에서는 클립보드와 외부 채팅 주소 설정을 시험용으로 대체하여 **Microsoft에 접속하거나 메시지를 전송하지 않아요.** 각 검사 결과와 통과·실패 수를 화면에 표시해요. OCR 첫 실행은 언어 자료를 불러와 다소 오래 걸릴 수 있어요. 별도 검사 패키지는 필요 없어요.

현재 기존 준비 도구는 Windows의 경로 구분자와 Tesseract.js 패키지의 실제 라이선스 이름(`LICENSE.md`) 차이 때문에 준비에 실패할 수 있어요. 이 채팅 변경은 준비 도구를 수정하지 않아요. 준비 오류가 나면 관리자에게 실행 결과를 전달하세요. 의존성을 준비하지 못한 경우 PDF·OCR 검사는 통과한 것이 아니에요.

PDF 예제를 다시 만들려면 아래 명령을 실행하세요.

```sh
python3 tools/make_fixtures.py
```

학생은 홈페이지에서 예제를 직접 골라 표·미리보기·PDF 페이지 전환·OCR 신뢰도·오류 안내를 확인하세요. 일반 PDF의 2페이지를 표시한 상태에서도 복사한 JSON에 1·2페이지가 모두 있는지, 민감한 내용 확인 전에는 복사할 수 없는지, 손상 파일·파일 재선택 뒤 이전 JSON이 남지 않는지도 확인하세요. 공개 가능한 예제로만 실제 채팅을 열어 로그인 없이 입력창이 보이는지, 직접 붙여넣어 전송한 자료에 답변이 오는지 확인하세요. 모바일에서는 전체 결과 확인·직접 복사·채팅 닫기도 확인하세요. **실제 Microsoft 채팅·클립보드 권한·응답·길이 제한·비용은 자동 검사의 대체 기능으로 확인하지 않으며, 학생 본인의 실제 확인을 대신하지 않아요.**

## 누락 탐지 에이전트 시험 준비

정상·누락 예제 PDF를 만들고, 사람이 별도로 확인한 정답과 에이전트 응답을 대조해 **찾은 누락·놓친 누락·잘못 지적한 항목**을 기록하는 독립 도구를 추가했어요. 홈페이지와 연결하지 않아요. 실제 에이전트 성능 시험은 아직 실행하지 않았으며 새 예제의 정답도 사람 확인이 필요해요.

준비·실행·정답 분리·팀 공유 기록 방법은 [평가 안내](evaluation/README.md)에 있어요. **에이전트에는 생성된 `agent-input` 안의 도면과 요청문만 전달하고, 정답이나 저장소 전체를 전달하지 마세요.**

## 1. 할 일을 하나 적어요

GitHub의 **Issues → New issue**에서 양식을 고르세요.

- **기능 요청**: 새로 만들고 싶은 것. 예: “완료한 할 일만 보고 싶어요.”
- **버그 신고**: 잘못 동작하는 것. 예: “저장을 한 번 눌렀는데 두 개가 생겨요.”

한 번에 작은 일 하나만 적고, **어떻게 되면 완료인지** 써 주세요.
팀에서 담당자 한 명을 정해 **Assignees(담당자)**에 지정하세요.
이슈가 만들어지면 붙는 번호(예: `#3`)를 기억하세요.

## 2. Copilot에게 만들어 달라고 해요

담당자는 Copilot 앱에서 저장소를 열고, 그 이슈를 위한 **별도 작업 공간**을 준비하세요.
**브랜치**는 팀의 원본과 섞이지 않게 작업을 나누는 방법이에요. 원본인 `main`에서 바로 작업하지 마세요.
분리 방법을 모르겠다면 변경하기 전에 Copilot에게 물어보세요.

아래 문장의 `#3`을 내 이슈 번호로 바꿔 요청하세요.

> 이슈 #3을 확인해줘. 현재 브랜치와 작업 공간이 다른 작업과 분리되어 있는지 확인하고, 작업 범위와 검증 방법을 쉽게 설명한 뒤 구현해줘.

설명을 읽고 원하는 방향인지 확인하세요. 요청과 다른 내용이 있으면 바로 알려 주세요.

## 3. 검토를 요청해요

작업이 끝나면 Copilot에게 **“이 변경으로 PR을 만들어줘”**라고 요청하세요.
**PR**은 “제가 만든 내용을 팀의 원본에 합쳐도 될까요?”라는 검토 요청이에요.

**PR을 만들기만 하면 리뷰가 자동으로 시작되지는 않아요.**
PR 생성 후 안내에 따라 앱에서 리뷰용 에이전트인 **`student-reviewer`**를 직접 선택하고 요청하세요.

> PR #5를 이슈 #3의 완료 조건에 맞춰 검토해줘.

`#5`는 내 PR 번호, `#3`은 연결 이슈 번호로 바꾸세요. 이슈가 없다면 PR 번호만 적어도 돼요.
이 문장은 요청 예시이며, 실제 에이전트 선택 방법은 앱에서 확인하세요. 검토 결과는 앱에 표시되며 GitHub에 자동으로 게시되지는 않아요.
검토에서 문제가 나오면 개발을 맡은 에이전트에게 수정을 요청하고, 필요한 검사를 다시 한 뒤 리뷰를 다시 요청하세요.
리뷰어가 보이지 않거나 이슈·코드를 읽지 못하면 팀 관리자에게 알려 주세요.

## 4. 내가 직접 써 보고 합쳐요

PR에 적힌 **확인 순서와 기대 결과**를 따라 직접 사용해 보세요. 방법이 없으면 Copilot에게 설명을 요청하세요.
원하는 대로 동작하는지 확인한 뒤 **학생 확인란은 본인이** 체크하세요.

**Copilot이 “검사 통과”라고 해도 직접 확인한 것은 아니에요.**
문제가 없고, GitHub에서 요구하는 검사와 팀원의 승인이 끝나면 권한 있는 사람이 **머지(팀의 원본에 합치기)**해요.
버튼이 막혀 있으면 우회하지 말고 관리자에게 물어보세요.

## 이것만은 기억해요

- 비밀번호·API 키(서비스 접속용 비밀값)·개인정보는 채팅, 코드, 이슈, 화면 캡처에 넣지 않아요.
- 다른 사람의 작업을 지우지 않아요. 로그인·권한·결제·데이터 삭제 같은 중요한 변경은 팀과 먼저 상의해요.
- 모르는 내용은 “초보자도 이해할 수 있게 설명해줘”라고 요청해도 괜찮아요.
