# Copilot과 함께 만드는 우리 팀 프로젝트

코드를 잘 몰라도 괜찮아요. **할 일을 적고 → Copilot과 만들고 → 직접 확인하는 순서**로 시작해 보세요.
이 저장소에는 협업 안내와 양식, DXF·PDF에서 선·원·글자를 읽는 기능이 있어요. 스캔 PDF는 사진 이미지에서 글자를 찾고, 선·원은 검토할 후보로 표시해요. DXF 읽기 결과는 복사해서 Studio의 검토 에이전트에 직접 전달할 수 있고, ② 분석 또는 ③ 검토 결과 JSON은 홈페이지에 직접 붙여 넣어 볼 수 있어요. 홈페이지는 사용자가 **피드백 받기**를 눌렀을 때만 ② 결과와 원본 PDF를 ③에 보내요. 가공방법을 추천하거나 도면을 수정하지는 않아요.

## DXF·PDF 읽기

Python 3가 설치된 상태에서 저장소 폴더의 터미널에 아래 명령을 차례로 입력하세요.

```sh
python3 tools/setup_readers.py
python3 -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 <http://127.0.0.1:8000/>을 여세요. `index.html`을 직접 여는 방식은 모듈·PDF 작업 도구를 불러올 수 없어 지원하지 않아요. 서버는 `Ctrl+C`로 종료해요.

DXF만 사용할 때는 첫 번째 준비 명령 없이 두 번째 서버 실행 명령만 사용해도 돼요. PDF·스캔 PDF는 준비 명령이 필요해요.

이전에 열어 둔 시험 화면의 서버가 종료되면 연결 설정을 불러오지 못할 수 있어요. 위 명령으로 홈페이지를 다시 실행하고 해당 주소를 열어 주세요. 저장된 결과는 브라우저와 주소별로 따로 보관되므로 `localhost`와 `127.0.0.1` 중 사용하던 주소를 계속 이용해 주세요.
준비 명령에서 `준비 완료: vendor/pdfjs/ 및 vendor/tesseract/ (라이선스 포함)`이 출력되는지 확인하세요. 홈페이지가 열려도 준비가 끝나지 않으면 PDF를 읽을 수 없어요. `PDF 읽기 도구를 불러오지 못했어요`라는 오류가 나오면 준비 명령을 실행하고, 홈페이지를 새로고침한 뒤 파일을 다시 선택하세요.

준비 명령은 공개 npm 저장소의 **PDF.js 6.4.299**, **Tesseract.js 6.0.1**, **Tesseract.js Core 6.1.2**와 Tesseract Fast의 한국어·영어 OCR 학습 자료를 내려받아요. npm 패키지는 고정된 SHA-512로, 학습 자료는 고정된 Git 파일 해시로 확인해요. 도구·학습 자료와 라이선스는 `vendor/pdfjs/`, `vendor/tesseract/`에 저장되며 Git에는 포함되지 않아요. 처음 준비할 때 인터넷이 필요하고, 한국어·영어 OCR 자료 약 5.5MB와 실행 도구가 내려받아져요. **이 브라우저에서만 읽기**를 선택하면 도면을 외부로 보내지 않아요. 단, DXF 결과 화면의 [검토 에이전트용 자료](#dxf-도면을-검토-에이전트에-보내기)를 사용자가 직접 Copilot Studio에 붙여넣으면 그 내용은 외부 서비스로 전달돼요. **②로 도면 분석하기**는 도면을 Microsoft에 보내요. Node.js·npm 설치나 빌드 과정은 필요 없어요.

- DXF 또는 PDF를 하나 선택하고 **이 브라우저에서만 읽기**를 누르세요. 선·원·글자의 내용과 위치를 표와 미리보기로 보여줘요. PDF는 페이지를 바꿔 확인할 수 있어요.
- DXF는 2차원 모형 공간의 `LINE`, `CIRCLE`, `TEXT`, `MTEXT`, `LWPOLYLINE` 직선 구간을 읽어요. 위치는 원본 좌표이며 오른쪽·위쪽이 +방향이고, 단위는 DXF의 `$INSUNITS`를 표시해요. UTF-8과 일부 명시된 기존 인코딩을 지원해요.
- 일반 PDF는 저장된 직선 경로·글자를 읽어요. 스캔 PDF나 이미지가 들어간 페이지는 한국어·영어 OCR로 이미지 속 글자를 찾고, 이미지 분석으로 선·원 후보를 찾으며 모두 **확인 필요**로 표시해요. OCR 신뢰도가 80%보다 낮은 글자는 인식 신뢰도와 함께 별도 표시해요. OCR은 사진 글자를 추정하는 기능이라 치수와 한글이 틀릴 수 있어 원본과 비교해야 해요.
- PDF 위치는 회전·잘라내기가 반영된 각 페이지 왼쪽 위 기준으로 오른쪽·아래쪽이 +방향이며, 단위는 포인트(1/72인치)예요. 일반 PDF의 원은 네 개의 닫힌 곡선으로부터 추정하므로 **확인 필요**로 표시해요.
- 미리보기는 읽은 요소를 재구성한 것이며 원본 뷰어가 아니에요. 글꼴·서식·정렬·잘림·숨김 표시·선 두께를 재현하지 않아요. 표의 글자 위치는 DXF 삽입점 또는 PDF 글자 시작 기준점이에요.
- 미지원 요소와 이미지 페이지는 **확인 필요**로 안내해요. 스캔 이미지에서 글자를 찾지 못하면 원인을 알려주고, 읽을 수 있는 요소가 전혀 없거나 파일이 손상되면 오류를 표시하며 성공 화면으로 이동하지 않아요.
- 바이너리 DXF, 3차원 도면, 블록 내부 요소, 복잡한 치수·일반 곡선, 암호가 걸린 PDF는 아직 지원하지 않아요. 스캔 PDF의 선·원은 제한된 이미지 탐지의 후보이므로 정확성을 보장하지 않아요. 사진이 기울거나 흐릴 때 OCR·도형 인식률이 낮을 수 있어요.
- **도면 다시 선택**을 누르면 처음 화면으로 돌아가요. 검도·가공방법 추천·수정본 영역은 아직 화면 틀이며, 파일을 판단하거나 수정하지 않아요.

### DXF 도면을 검토 에이전트에 보내기

DXF를 읽으면 결과 화면에 **검토 에이전트용 자료 (DXF)** 칸이 나타나요. 읽은 선·원·글자를 Copilot Studio의 ③ 도면 검토 에이전트가 받는 ② 형식 JSON으로 바꾼 것이에요(`src/agent-input.js`). 원본 DXF 파일은 바꾸지 않아요.

1. **검토 에이전트용 자료 복사**를 눌러요. 자동 복사가 막히면 칸 안의 내용을 직접 복사해요.
2. Copilot Studio에서 ③ 도면 검토 에이전트의 **새 대화**를 열고 붙여넣어요. 요청문이 자료 앞에 들어 있어요.
3. 에이전트가 설명한 빠진 부분과 이유를 원본 도면과 직접 비교해요.

- **외부 전송 안내**: 붙여넣는 순간 파일 이름과 도면의 글자·좌표가 외부 서비스(Microsoft Copilot Studio)로 전달돼요. 홈페이지가 자동으로 보내지는 않아요. 개인정보나 기밀이 없는 도면만 사용하세요.
- 읽기 기능이 지원하지 않는 요소(치수 `DIMENSION`, 블록 `INSERT`, 원호 등)는 자료의 `limitations`에 **확인 필요**로 적혀요. 요청문에서도 이런 요소의 정보를 “도면에 없음”으로 단정하지 말라고 안내해요. 다만 에이전트가 이 안내를 반드시 따른다는 보장은 없으니 결과를 직접 확인하세요.
- 형상과 치수의 연결(`features`)은 만들지 않아요. 글자가 어떤 형상의 치수인지는 에이전트가 위치를 보고 판단하며, 확실하지 않으면 확인 대상으로 남겨요.
- ② 에이전트의 6단계 분석을 실행한 자료가 아니므로 상태는 항상 **부분 완료**예요. 빈 목록이 있다고 도면에 정보가 없다는 뜻은 아니에요.
- 기호가 바뀐 글자(`%%c` → `Ø` 등), 여러 줄 글자(`MTEXT`), 기본 정렬이 아닌 글자는 표와 에이전트 자료에 **확인 필요**로 남겨요. `raw_text`에는 표시용 글자, `dxf_raw_text`에는 변환 전 문자 코드를 따로 보존해요. 쌓아 쓴 공차처럼 해석하지 못한 서식은 원본과 대조해야 해요.
- 큰 도면은 자료가 길어져 붙여넣기가 잘릴 수 있어요. 칸 아래의 글자 수를 참고하고, 잘렸다면 결과를 믿지 마세요.
- PDF는 이 칸이 나타나지 않아요. PDF는 기존처럼 Studio에 파일을 직접 첨부해요.

시험용 DXF는 `review-a.dxf`, `review-b.dxf`, `review-c.dxf`를 사용할 수 있어요. 홈페이지에서 내려받아 선택한 뒤 자료를 복사하세요. 세 파일은 개인정보·기밀이 없는 가상 자료예요. **Studio에는 각 파일의 복사 자료만 보내고, [시험 안내의 비교 기준](docs/copilot-studio/README.md#dxf-도면-연결-33)이나 저장소 전체를 보내지 마세요.**

### 간단 AI 도면 검토

1. 연결된 홈페이지에서 PDF를 선택하고 전송 동의를 확인한 뒤 **도면 분석하기**를 누르세요. 최대 16MiB PDF를 지원해요. DXF는 PDF로 변환해야 해요.
2. ② 분석이 끝나면 **피드백 받기**를 눌러 ③에 요청하세요. 이때 원본 PDF와 ② 결과가 함께 전송돼요. 요청 전이나 연결 오류가 난 뒤에도 **② 분석 결과 자세히 보기**를 열 수 있어요.
3. ③의 쉬운 요약과 카드형 확인 사항이 먼저 보여요. ②의 자세한 분석은 접힌 항목에 있어요. 검토에는 몇 분이 걸릴 수 있고, **기다리기 중단**은 화면의 대기만 멈춰요. 결과는 참고용이므로 원본과 직접 비교하세요.

②·③ 응답은 이 브라우저에 자동 저장돼요. 첫 화면의 **저장된 결과와 추가 기능**에서 분석 또는 검토 결과를 다시 열 수 있어요. 저장된 ② 결과만 있는 경우에도 피드백을 요청할 수 있지만, 원본 PDF는 브라우저에 저장하지 않으므로 같은 파일을 다시 골라야 해요. 결과는 이 브라우저를 쓰는 사람에게 보이고 저장 공간을 지우면 사라질 수 있어요. 추가 기능에서 저장된 분석을 확인해 참고 예제로 내려받을 수도 있어요. 참고 예제에는 파일 이름·좌표는 빠져도 도면에 적힌 치수·글자가 포함되므로 공개해도 되는 자료만 사용하세요.

② 분석을 시작하면 PDF가 Microsoft Copilot Studio로 전송되고, **피드백 받기**를 누르면 같은 PDF가 ③으로 다시 전송돼요. 사용량이 발생하거나 첨부 파일이 서비스의 보관 정책에 따라 남을 수 있어요. 도면을 보낼 권한이 있고 개인정보·기밀이 없는지 확인하세요. **이 브라우저에서만 읽기**는 도면을 외부로 전송하지 않아요.

현재 저장소에는 Cloudflare Worker와 Netlify Edge Function의 공개 홈페이지용 연결 중계 코드를 준비했지만, 어느 쪽도 실제 호스팅에 설정하거나 배포하지 않았어요. 배포되면 이용자는 별도 파일이나 주소 입력 없이 쓸 수 있고, 연결 담당자는 호스팅 서비스에 한 번만 설정하면 돼요. 현재 로컬 시험 방식은 작업 공간마다 `agent-connection.local.json`이 필요합니다.

공개 서비스의 기본 준비 명령은 `python3 tools/setup_readers.py` 다음 `python3 tools/build_site.py`예요. 빌드 결과는 Git에서 제외되는 `dist/`에 만들어지며 `index.html`, 필요한 읽기 도구와 가상 예제만 복사해요. 저장소 문서와 평가 자료는 사이트 파일에 넣지 않습니다. `wrangler.jsonc`는 Cloudflare Worker 정적 파일 제공과 `/api/*` 연결 경로, 분당 3회 제한 설정을 준비합니다. 제한은 위치별로 대략 적용되며 엄격한 비용 상한은 아닙니다.

Netlify에서는 사이트 설정의 Edge Functions 환경 변수로 `ANALYSIS_TOKEN_ENDPOINT`, `REVIEWER_TOKEN_ENDPOINT`, `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`를 설정해야 합니다. 비밀 값과 연결 주소는 코드나 `netlify.toml`에 넣지 마세요. Netlify의 `/api/studio-token` 경로에는 IP·도메인별 분당 3회 제한을 설정했지만, 이는 모든 방문자를 합산한 사용료 한도가 아니며 초과 요청 차단도 즉시 적용되지 않을 수 있어요. `netlify.toml`은 `python3 tools/setup_readers.py`와 `python3 tools/build_site.py`로 `dist/`를 만들도록 준비돼 있어요. Cloudflare 쪽은 `ANALYSIS_TOKEN_ENDPOINT`, `REVIEWER_TOKEN_ENDPOINT`, `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`를 서버에 각각 설정해야 합니다. 두 방식 모두 연결 주소를 브라우저에 내려주지 않고 보안 확인 뒤 짧은 시간 동안 쓰는 Direct Line 토큰만 전달합니다. PDF는 브라우저에서 Microsoft Copilot Studio로 직접 전송되고 토큰 발급 서버에는 올라가지 않습니다. 보안 확인 과정에서 이용자 접속 정보가 Cloudflare Turnstile에 전달됩니다. ②와 ③의 서로 다른 주소가 모두 필요하며, ② 주소를 ③에 재사용하면 안 됩니다.

Netlify 중계 코드는 준비됐지만 배포하거나 Netlify 설정을 바꾸지 않았어요. 현재 확인된 것은 로컬 컴퓨터의 ② 연결뿐이며, ③ 연결 주소는 아직 준비되지 않았습니다. 그래서 공개 자동 연결은 사용할 수 없어요. 공개 전 두 에이전트의 주소·게시 상태를 확인하고, 계정 소유자가 환경 변수 설정과 배포를 별도로 승인해야 합니다. Netlify 사용량이나 Microsoft Copilot Studio 사용량에 따라 비용이 생길 수 있고, 코드의 요청 제한은 사용료를 보장하거나 엄격히 막지 않아요. 실제 연결 주소나 보안 키를 코드·이슈·채팅에 붙여 넣지 마세요.

③ 결과에는 쉬운 요약과 위치·문제·이유·확인 방법이 담긴 카드가 먼저 보여요. ② 분석 결과는 **② 분석 결과 자세히 보기**에 접혀 있어요. ②가 축으로 분류하면 코드가 연결이 확인된 형상·치수 표기만 짧게 정리해 ③ 결과와 함께 보여 줘요. 축으로 분류되지 않거나 연결·판독이 불확실한 값은 설명에 넣지 않으며, 설계 적합성이나 KS 기준 준수도 판정하지 않아요. ③ 응답은 V4 JSON 형식이어야 해요. ②·③ 응답은 이 브라우저에 저장되며, 저장된 결과에서 다시 열 수 있어요. 저장 공간이 부족하면 화면에 저장 실패를 알려요. ③ 연결이 실패하거나 응답을 읽지 못해도 ② 결과는 화면과 저장 기록에서 확인할 수 있어요. 저장된 ② 결과로 피드백을 요청할 때는 분석에 사용한 원본 PDF를 다시 골라야 해요. 사람은 원본 도면과 직접 비교해야 하고, 결과는 다른 기기와 동기화되지 않아요.

이미 받은 ② 분석 결과나 ③ 검토 결과를 보관하려면 **기존 결과 직접 보기**에서 응답이나 JSON을 붙여 넣고 **결과 보기**를 누른 다음 **이 결과 저장**을 누르세요. ③은 V4의 `schema_version: "2.0"` 형식을 읽어 상태·요약·지적·근거·남은 한계를 보여 줘요. `human_review_status`는 반드시 `미확인`으로 남으며 홈페이지가 사람의 도면 대조를 대신하지 않아요. 직접 입력한 내용은 저장 버튼을 누르기 전까지 브라우저 안에서만 처리하고 저장하지 않으며, 누르면 이 브라우저에만 보관돼요. 첫 화면의 저장 목록에서 다시 열거나 삭제할 수 있고, **처음으로** 또는 **도면 다시 선택**을 누르면 입력 화면의 내용은 지워져요.
### 예제와 자동 검사

개인정보 없는 직접 만든 예제를 `tests/fixtures/`에 두었어요.

| 예제 | 기대 결과 |
|---|---|
| `simple.dxf` | 선 1개: (20, 30) → (140, 30), 원 1개: 중심 (200, 130)·반지름 25, 글자 ‘도면 예제’: (20, 190), 단위 mm |
| `review-a.dxf`, `review-b.dxf`, `review-c.dxf` | ③ 검토 에이전트 전달용 가상 DXF. 비교 기준은 위 시험 안내에서 별도로 확인 |
| `simple.pdf` | 1페이지: 선 (20, 210) → (140, 210), 원 중심 (200, 110)·반지름 25, ‘Hello blueprint’ (20, 50). 2페이지: 회전·잘라내기·중첩 좌표 변환을 반영한 선 2개와 글자 1개, 타원은 제외 안내 |
| `scan.pdf` | 이미지 속 ‘5 mm’를 OCR로 처리해 숫자 ‘5’를 찾고, 낮은 신뢰도의 나머지 글자는 ‘확인 필요’로 표시. 선 (25, 70) → (150, 70), 원 중심 (230, 120)·반지름 약 27.5의 후보도 확인 필요로 표시 |
| `scan-only.pdf` | 글자나 도형이 없는 이미지 PDF. 글자를 찾지 못했다는 안내와 오류 표시 |
| `mixed.pdf` | 첫 페이지의 일반 요소와 둘째 페이지의 이미지 속 OCR 글자·선·원 후보 모두 표시 |
| `paths.pdf` | 사각형의 선 4개와 삼각형의 선 3개, 그리지 않은 경로는 제외 |
| `broken.pdf` | 손상된 PDF라는 오류 안내 |

서버 실행 후 <http://127.0.0.1:8000/tests/>를 열면 브라우저에서 자동 검사가 실행돼요. 개수·좌표·일반 및 스캔 글자·페이지 전환·손상 파일·기존 결과 제거, ②·③ 결과 표시·연결 오류, DXF 검토 에이전트용 자료 변환을 검사하며, 각 검사 결과와 통과·실패 수를 화면에 표시해요. 자동 연결 검사는 가짜 응답으로 진행하므로 Studio에 파일을 보내거나 사용량을 발생시키지 않아요. OCR 첫 실행은 언어 자료를 불러와 다소 오래 걸릴 수 있어요. 별도 검사 패키지는 필요 없어요.

②·③ 결과 표시와 자동 연결 처리만 확인할 때는 <http://127.0.0.1:8000/tests/?agent=1>을 여세요. 이 주소는 에이전트 결과·연결 검사만 실행해요.

DXF만 검사하려면 <http://127.0.0.1:8000/tests/?suite=dxf>를 여세요. PDF 도구 없이 실행할 수 있으며, **실행하지 않은 PDF·OCR 검사는 통과로 세지 않아요.** DXF 줄바꿈, 글자의 원래 코드와 확인 필요, 작은 좌표 보존, 미지원 요소, 가상 예제, 자료 복사·복사 실패 안내를 확인해요. 복사 자동 검사는 브라우저 복사 기능을 시험용으로 대체하므로 실제 브라우저의 복사 권한도 별도로 확인해야 해요.

PDF 예제를 다시 만들려면 아래 명령을 실행하세요.

```sh
python3 tools/make_fixtures.py
```

학생은 홈페이지에서 예제를 직접 골라 표·미리보기·PDF 페이지 전환·OCR 신뢰도·오류 안내를 확인하세요. 자동 검사 통과는 학생 본인의 실제 도면 확인을 대신하지 않아요.

## 누락 탐지 에이전트 시험 준비

정상·누락 예제 PDF를 만들고, 사람이 별도로 확인한 정답과 에이전트 응답을 대조해 **찾은 누락·놓친 누락·잘못 지적한 항목**을 기록하는 독립 도구를 추가했어요. 홈페이지와 연결하지 않아요. 실제 에이전트 성능 시험은 아직 실행하지 않았으며 새 예제의 정답도 사람 확인이 필요해요.

준비·실행·정답 분리·팀 공유 기록 방법은 [평가 안내](evaluation/README.md)에 있어요. **에이전트에는 생성된 `agent-input` 안의 도면과 요청문만 전달하고, 정답이나 저장소 전체를 전달하지 마세요.**

## 1. 할 일을 하나 적어요

GitHub의 **Issues → New issue**에서 양식을 고르세요.

- **기능 요청**: 새로 만들고 싶은 것. 예: “완료한 할 일만 보고 싶어요.”
- **버그 신고**: 잘못 동작하는 것. 예: “저장을 한 번 눌렀는데 두 개가 생겨요.”

한 번에 작은 일 하나만 적고, **어떻게 되면 완료인지** 써 주세요.
팀에서 담당자 한 명을 정해 **Assignees(담당자)**에 지정하세요.
이슈가 만들어지면 붙는 번호(예: `#3`)를 기억하세요.

## 2. Copilot에게 만들어 달라고 해요

담당자는 Copilot 앱에서 저장소를 열고, 그 이슈를 위한 **별도 작업 공간**을 준비하세요.
**브랜치**는 팀의 원본과 섞이지 않게 작업을 나누는 방법이에요. 원본인 `main`에서 바로 작업하지 마세요.
분리 방법을 모르겠다면 변경하기 전에 Copilot에게 물어보세요.

아래 문장의 `#3`을 내 이슈 번호로 바꿔 요청하세요.

> 이슈 #3을 확인해줘. 현재 브랜치와 작업 공간이 다른 작업과 분리되어 있는지 확인하고, 작업 범위와 검증 방법을 쉽게 설명한 뒤 구현해줘.

설명을 읽고 원하는 방향인지 확인하세요. 요청과 다른 내용이 있으면 바로 알려 주세요.

## 3. 검토를 요청해요

작업이 끝나면 Copilot에게 **“이 변경으로 PR을 만들어줘”**라고 요청하세요.
**PR**은 “제가 만든 내용을 팀의 원본에 합쳐도 될까요?”라는 검토 요청이에요.

**PR을 만들기만 하면 리뷰가 자동으로 시작되지는 않아요.**
PR 생성 후 안내에 따라 앱에서 리뷰용 에이전트인 **`student-reviewer`**를 직접 선택하고 요청하세요.

> PR #5를 이슈 #3의 완료 조건에 맞춰 검토해줘.

`#5`는 내 PR 번호, `#3`은 연결 이슈 번호로 바꾸세요. 이슈가 없다면 PR 번호만 적어도 돼요.
이 문장은 요청 예시이며, 실제 에이전트 선택 방법은 앱에서 확인하세요. 검토 결과는 앱에 표시되며 GitHub에 자동으로 게시되지는 않아요.
검토에서 문제가 나오면 개발을 맡은 에이전트에게 수정을 요청하고, 필요한 검사를 다시 한 뒤 리뷰를 다시 요청하세요.
리뷰어가 보이지 않거나 이슈·코드를 읽지 못하면 팀 관리자에게 알려 주세요.

## 4. 내가 직접 써 보고 합쳐요

PR에 적힌 **확인 순서와 기대 결과**를 따라 직접 사용해 보세요. 방법이 없으면 Copilot에게 설명을 요청하세요.
원하는 대로 동작하는지 확인한 뒤 **학생 확인란은 본인이** 체크하세요.

**Copilot이 “검사 통과”라고 해도 직접 확인한 것은 아니에요.**
문제가 없고, GitHub에서 요구하는 검사와 팀원의 승인이 끝나면 권한 있는 사람이 **머지(팀의 원본에 합치기)**해요.
버튼이 막혀 있으면 우회하지 말고 관리자에게 물어보세요.

## 이것만은 기억해요

- 비밀번호·API 키(서비스 접속용 비밀값)·개인정보는 채팅, 코드, 이슈, 화면 캡처에 넣지 않아요.
- 다른 사람의 작업을 지우지 않아요. 로그인·권한·결제·데이터 삭제 같은 중요한 변경은 팀과 먼저 상의해요.
- 모르는 내용은 “초보자도 이해할 수 있게 설명해줘”라고 요청해도 괜찮아요.
